## 学习目标与项目地图

这是一个本地生活点评应用。用户可以验证码登录、浏览和搜索商户、查看附近商户、发布与点赞探店笔记、关注用户、浏览关注流，并参与优惠券秒杀。前端通过统一 Axios 客户端访问 API；后端由 Gin 接收请求，按 handler、service、GORM Gen/Redis 分层处理；MariaDB 保存业务事实，Redis 承担会话、缓存、关系集合、时间序列、地理索引与秒杀队列。

```text
Vue 页面 / Pinia / Axios
  -> 开发环境 Vite proxy，部署环境 Nginx /api rewrite
  -> Gin 全局中间件与路由级登录校验
  -> handler：绑定参数、转换 HTTP 响应
  -> service：业务规则与数据源协作
  -> GORM Gen / Redis
  -> MariaDB 持久化、Redis 临时状态或索引
```

### 模块职责

| 模块 | 主要职责 | 代表入口 |
| --- | --- | --- |
| `frontend/src` | 页面、路由守卫、会话状态、API 契约和滚动交互 | `utils/request.js`、`router/index.js` |
| `cmd/server`、`pkg/app` | 配置读取、Wire 依赖组装、服务启停 | `main.go`、`wire/wire_gen.go` |
| `internal/server`、`internal/middleware` | Gin 路由、跨域、日志、会话恢复、鉴权 | `http.go`、`refresh_token.go` |
| `internal/handler`、`api/v1` | 参数绑定、DTO、统一响应 | `user.go`、`blog.go` |
| `internal/service` | 登录、商户、社交和秒杀用例 | `user.go`、`shop.go`、`voucher_order.go` |
| `internal/base` | 泛型缓存、Redis ID、锁和用户上下文 | `cache_client.go`、`redis_worker.go` |
| `internal/model`、`internal/query` | GORM Gen 生成的模型与类型安全查询 | `gen.go`、各表生成文件 |
| `deploy/docker-compose` | MariaDB/Redis/Nginx 本地依赖与反向代理 | `docker-compose.yml`、`nginx.conf` |

### 代表性端到端链路

1. **验证码登录**：登录页 -> Axios -> `/user/code`、`/user/login` -> Redis 验证码 -> MySQL 用户 -> Redis Hash 会话 -> Pinia 保存 token。后续请求由前端附加 Bearer token，后端恢复用户并滑动续期。
2. **商户查询**：列表或详情页 -> `/shop/...` -> Redis 缓存或 GEO 索引 -> MySQL 回源/补全 -> 统一响应 -> Vue 渲染距离、排序和分页结果。
3. **关注内容流**：发布笔记 -> MySQL 保存 -> Redis ZSet 推送收件箱；关注页用时间戳和同分值偏移滚动读取，再补全作者与点赞态。当前推送目标字段存在确定风险，课程会解释其影响与正确语义。
4. **秒杀下单**：详情页 -> 登录校验 -> Redis ID -> Lua 原子检查库存/重复购买并写 Stream -> 消费者加用户锁 -> MySQL 事务查重、条件扣库存、保存订单 -> ACK。当前消费组初始化、唯一约束和前端券信息联表尚未闭环。

## 学习重点与记忆提纲

- **先懂职责与状态归属（C01-C03）。** 前端负责交互和凭据传输，服务端负责鉴权与业务规则；Wire 生成构造调用，Redis 保存共享会话。记住完整请求链与“最后活跃后 30 分钟失效”的含义。
- **再懂索引与事实源（C04-C07）。** MySQL 保存业务事实，Redis 分别承担缓存、空间候选、集合和时间序列；不同结构只解决相应查询问题，双写不自动具有事务性。记住 Cache-Aside 更新顺序、坐标约定、同分值游标和当前实现缺口。
- **重点懂原子边界（C08-C09）。** Lua 保护 Redis 内步骤，事务保护 MySQL 内步骤，消息连接两者。记住“准入成功不等于落库成功”“提交后 ACK 仍可能重放”，以及唯一约束和补偿尚未闭环。
- **最后懂证据边界（C10）。** 代理配置、实际进程、编译记录、功能正确和性能数据分别说明不同问题。记住不能将负载均衡说成高可用，将构建成功说成并发正确。

每课先看“本课重点”，沿主链和源码理解原因，再用“需要记住什么”整理结论；需要面试表达时跳到关联的[面经](面经.md)。
