谁规定能力，谁真正干活？

看懂 NewUserService 为什么返回接口，却创建一个结构体对象。

需要看执行顺序、变量里的值和 s 的用途时，先打开发短信执行演示，按“创建实例 → 返回指针的接口值 → 调用方法 → 修改同一实例”逐步操作。

01 / 已有经验

先想一个你熟悉的 TypeScript 对象

interface UserService {
  sendCode(phone: string): void;
}

const userService: UserService = {
  sendCode(phone) {
    console.log("给这个手机号准备验证码：", phone);
  }
};

userService.sendCode("13800138000");

interface 规定：这个对象必须有一个 sendCode 方法。真正执行打印的是下面的方法体。

对象满足接口要求，才能赋给 UserService 类型的变量。变量调用方法时，执行的是实际对象里的实现。

Go 项目也有“规定能力”和“写出实现”两个角色，只是它把结构体定义和方法定义分开写。

这里只类比角色。后面的 Go 示例返回 error，与 TS 的 void 不同；Go 的普通接口由方法约束组成，不能照搬 TS 接口里的数据字段。

小练习：上面的 interface 扮演什么角色？

复习答案：能力约定。定义接口本身不会执行验证码逻辑。

02 / 一次只多一层

Go 把“类型”和“方法”分开写

先只保留一个手机号参数，把项目里的公共依赖暂时拿掉。这是教学示例。

// ① 接口：要求能调用 SendCode，返回一个 error。
type UserService interface {
    SendCode(phone string) error
}

// ② 结构体：定义具体类型，保存服务的数据。
type userService struct {
    senderName string
    sentCount  int
}

// ③ 方法：这里才写真正执行的代码。
func (s *userService) SendCode(phone string) error {
    s.sentCount++
    fmt.Println(s.senderName, phone, s.sentCount)
    return nil
}

type userService struct {...} 定义类型和字段。userService{...} 创建具体实例；方法用 s 读取这个实例的 senderName，并增加它的 sentCount。

p := &userService{senderName: "点评短信"}
err := p.SendCode("13800138000")

userService{} 创建结构体值，前面的 & 取得它的地址，所以 p 的类型是 *userService。

(s *userService) 表示：SendCode 是这个指针类型的方法。调用 p.SendCode(...) 时，方法里的 s 就是这次接收调用的 p，可以先类比 TS 的 this。

return nil 表示本次调用没有错误。这个演示通过 s 读写实例字段，并打印文字；实际验证码和 Redis 逻辑要看项目源码。

Go 用显式的接收者 s，没有 class 或自动的 this 关键字。也不需要写 implements；把具体值赋给接口时，编译器会核对方法是否齐全。参见 官方教程：隐式实现接口。

要加“校验手机号”的逻辑，应该改哪一段？

复习答案：实现方法。结构体保存字段，接口列出方法要求，方法体执行行为。

03 / 创建，再交给调用者

NewUserService 就是普通函数

func NewUserService() UserService {
    p := &userService{senderName: "点评短信"}
    return p
}

函数名里的 New 是命名习惯，意思是“创建一个”。Go 不会自动调用这个函数；需要启动代码主动调用它。

  1. p := &userService{}：创建具体对象，得到它的指针。
  2. return p：函数要求返回 UserService，编译器检查 *userService 有没有所需方法。
  3. 方法齐全，返回的接口值携带这个具体指针；调用接口方法时，执行具体实现。
创建对象NewUserService()
→
实际对象的指针*userService
→
返回接口值UserService
u := NewUserService()                 // u 的静态类型：UserService
err := u.SendCode("13800138000")       // 执行 (*userService).SendCode

把类型写成接口，是为了让使用方通过规定的方法使用服务。在项目里，Handler 就通过 UserService 调用用户业务。将来换成另一个实现，也必须满足这个接口要求。

构造函数并不必须返回接口；这是本项目的设计选择。接口值也不会把对象“变成另一个对象”。参见 官方说明：构造函数与结构体字面量。

先理解上面，再看：为什么删掉 & 会报错？

这里的方法定义在 *userService 上。接口要求 SendCode，这个指针类型满足要求；结构体值类型 userService 的方法集不满足要求。

return &userService{}  // 类型 *userService：满足接口
return userService{}   // 类型 userService：不满足接口

能对一个可寻址的结构体变量调用指针方法，是编译器帮助补了取地址；把结构体值赋给接口时，没有这种自动补地址。先记住这条边界，方法集留到下一小节练。

参见 官方教程：接口与指针方法。这条结论针对当前指针接收者写法，不能推广成“返回接口永远要加 &”。

&userService{} 最后得到的是什么？

复习答案：对象地址，即指向结构体的指针值。

04 / 对照真实源码

原代码只是又带上了依赖和请求参数

type userService struct {
    *Service
}

func NewUserService(service *Service) UserService {
    return &userService{Service: service}
}

func (s *userService) SendCode(
    ctx context.Context, req *v1.SendCodeReq,
) error {
    // 校验手机号 → 准备验证码 → 写 Redis
    // 此处省略，完整逻辑见源码。
    return nil
}

Service 是本项目另一个结构体，保存 Redis 客户端、数据库查询对象、配置、日志等公共依赖。

*Service 是嵌入字段，它的字段名默认就是 Service。所以 Service: service 的左边是字段名，右边是函数参数：把传进来的公共依赖放进新对象里。

于是方法里可以通过 s.rdb 使用 Redis。在当前代码里，这相当于通过嵌入字段访问 s.Service.rdb。这里是字段嵌入，可以类比“对象里装了公共工具”，具体语义见 官方说明：Embedding。

ctx context.Context 是请求上下文，req *v1.SendCodeReq 是请求参数结构体的指针，手机号从 req.Phone 取。这两个参数先按用途理解即可。

项目实际链路：POST /user/code → UserHandler.SendCode 绑定手机号 → UserService.SendCode → (*userService).SendCode 校验并写 Redis → Handler 返回响应。

事实边界：目前源码只记录短信日志，没有接入第三方短信发送。真实 UserService 还要求 Login、Me 等其他方法；本课只截取 SendCode，不能用单方法示例覆盖项目接口。

  • internal/service/user.go：接口第 21–30 行，结构体与构造函数第 66–87 行，SendCode 第 89–113 行。
  • internal/service/service.go：公共依赖结构体第 19–25 行。
  • internal/handler/user.go：Handler 保存接口第 20–23 行，调用 SendCode 第 48 行。
